# 工作流节点审查与商品一致性优化

审查日期 2026-11-10。范围：`latest-workflows.zip` 里的 56 份 API 工作流、`program-source.zip` 里的生成脚本、自研节点和规则文档。

## 结论

商品走样的原因在路线本身，调参数解决不了：现在的主力工作流让模型**从纯噪声把商品重新画一遍**，实拍照片只是提示，没有任何节点约束模型照着画。

你自己的运行记录已经证明了这一点。快餐盘四角从 `corner_v01` 改到 `corner_v10`，换参考、调顺序、加到三张实拍、改提示词，都没有稳定；火锅盖碗 v09 被退回时你说的是「都不是原来的商品了」。十五张里唯一靠结构保住器型的是 B05 的 `photo_klein_v02`，它的做法正好相反：保留实拍像素，只让模型画食物。

所以优化方向是把 B05 那条诊断分支做成通用工作流：**商品像素直接来自实拍，模型只画落影、反光和食物**。新工作流在 `optimized/product_lock/`，用法见该目录 README。

## 现有节点逐项审查

以 `02_商品双参考与800输出` 和十五张快餐盘的实际运行图为准。

| 节点 | 现状 | 判断 |
|---|---|---|
| `EmptyFlux2LatentImage` 1024×1024 | 采样起点是空 latent | **根因。** 商品的每个像素都由模型合成，器型、花纹、颜色全靠模型「记住」参考图 |
| `ReferenceLatent` ×4–8 | 实拍和背景编码后挂到正负条件上 | **根因。** 这是软提示，不是约束。加参考、调顺序都不会变成硬锁，你的规则文档里也写了这一点 |
| `UnetLoaderGGUF` Klein 4B 蒸馏版 Q5_K_M | 4B 参数、4 步蒸馏、5 bit 量化 | 偏弱。这是 FLUX.2 里最小的型号又压了一道，保形能力最差。24 GB 内存放得下 Q8，量化不必压到 Q5 |
| `CLIPLoaderGGUF` Qwen3-4B Q4_K_M | 4 bit 量化 | 偏弱。配合下面的长提示词，细节指令容易丢 |
| `CLIPTextEncode` 正向 | 实测 210–474 个英文词 | 过长。大段文字描述器型（rim、collar、corners）会和参考图抢话语权。你已经发现 `bowed`、`flared` 这类词把四角越写越翘 |
| `CLIPTextEncode` 负向 + `CFGGuider` cfg=1.3 | 蒸馏模型上开 CFG | 不划算。蒸馏版按 cfg=1 训练，1.3 让每步多算一遍、耗时翻倍，负向词的作用却很弱；`distorted corners`、`round plate` 这类词还可能反向提示 |
| `ImageScale` 商品参考 | 3500×2000 的裁切缩到 1024×592 | 细节损失。缩小 3.4 倍后花纹已经糊了，青花这类纹样只能靠模型编 |
| `ImageScale` 背景参考 | 通用模板里 1024×1024，批量里 768×768 | 模板不合理。背景拿到的分辨率比商品还高（1.05 MP 对 0.6 MP）。批量脚本已改成 768，模板没同步 |
| `ImageScale` 的 `crop: disabled` | 宽高是手填的固定数 | 有隐患。批量脚本按比例算过，误差不超过 1.2%。但 `fission/graphs.py` 把商品参考缩成 `reference_size × reference_size` 的正方形，非正方形输入会被直接压扁；手工模板里的 `1024×816` 和 `ImageCrop (0,0)` 换图后也不会自动更新 |
| `Flux2Scheduler` 4 步 + `euler` | 蒸馏版标准配置 | 合理。但器型在第 1 步就定了，后面改不回来 |
| 可选二次采样 `flux2_tail2_96` | 低噪声尾段 2 步 | 合理但无关。它只提清晰度，不修几何，规则里也写明了 |
| `FissionPerspective` 二维拉伸 | A01 成图后把前沿两角下移 40 px | 治标。用后期变形去修一张已经画错的图，坐标只对这一张有效 |
| `FissionPhotoLock` + `SetLatentNoiseMask` | B05 诊断分支 | **方向正确。** 缺点是多边形手工描、脚本里写死了 B05 的路径、一次只支持一张实拍 |
| `ImageCrop` → `ImageScale` 800 → `SaveImage` | 取景和输出 | 合理 |
| 缓存、回执、哈希留档 | 每次运行绑定输入和模型哈希 | 合理，新工作流沿用 |

缺一个环节：成图出来后只靠人眼比对实拍，没有自动的一致性检查。新工作流里保护区可以逐像素核对，见 `verify_lock.py`。

## 优化后的工作流

`optimized/product_lock/build_locked_workflow.py` 按一份 JSON 配置生成 UI 和 API 两份工作流。

1. 每件商品输入一张透明底的实拍抠图，原始像素不动。
2. 抠图只做等比缩放后贴到已审背景上，得到布局图。高度由原图比例推出，没有能把商品拉高或压扁的参数。
3. 布局图既是采样起点，也是唯一的参考图，输出和它同尺寸。
4. `SetLatentNoiseMask` 把采样限制在许可区：商品外一圈落影环带、商品最外 3 px 的过渡边、食物许可区。
5. 最后用同一张蒙版把模型输出贴回布局图。保护区内，成图和实拍缩放图逐像素相同。

和现有路线相比：

| | 原生双参考（现有） | 商品像素锁定（新增） |
|---|---|---|
| 商品器型、花纹、颜色 | 模型重画，每张都要人眼核对 | 实拍像素，不会变 |
| 参考图数量 | 3–4 张，各 0.6–1 MP | 1 张 |
| CFG | 1.3，每步算两遍 | 默认 1.0 |
| 提示词 | 200–470 词，大半在描述器型 | 几十词，只写落影、光线、食物 |
| 多件、叠放、多色 | 易多画一只、串色（`mixed_v01` 出了九只碗） | 每件各用自己的实拍，数量和颜色由配置决定 |
| 视角 | 可以让模型换角度 | 只能用拍过的角度 |

最后一行是这条路线的代价：要什么角度，就得有那个角度的实拍。你的摄影师原片已经覆盖了正面浅俯拍、俯视和低侧视，日常主图够用。

## 我验证了什么，没验证什么

这台机器上没有 ComfyUI、模型和你的实拍图，所以**新工作流还没有真正出过图**。已做的是离线检查：

- 生成器自带的校验通过：63 个节点的必填输入齐全，每条连线两端类型一致。
- 用 numpy 按 ComfyUI 的运算规则模拟了全部蒙版和合成节点，把「模型输出」换成纯随机噪声，保护区改动为 0 像素，`verify_lock.py` 判定通过。
- 节点类型都取自你已经跑通的工作流，另加 `SolidMask`、`InvertMask`、`ConditioningZeroOut` 三个核心节点。前两个你的环境里没出现过，首次导入时请确认没有红色缺失节点。

需要你在本机验证的：

- 用 B05 的素材跑一张，和已通过的 `photo_klein_v02` 成图对比。
- 贴图感。商品实拍的光向、色温和背景不一致时会显得像贴上去的，你的规则文档里记过这个问题。对策是生成背景时就按实拍的光向和俯角写，并把 `edit_band_px` 调大让模型多画一些落影；设成 0 则整张背景交给模型围着商品重画。
- 抠图质量。边缘抠不干净会带一圈原背景色。

## 确实需要换角度时

没有对应角度的实拍、只能让模型生成时，下面几项能减轻走样，但不能根治。按性价比排序：

1. 选视角最接近目标构图的实拍作参考，提示词里要求保持该视角。
2. 提示词压到 150 词以内，删掉形容器型的词，器型交给参考图。
3. cfg 改回 1.0，去掉负向提示词。
4. 模型换成 Klein 4B 的 Q8 量化，文本编码器同样换 Q8。
5. 商品参考长边保持 1024 以上，背景参考降到 512–768。
6. 一次只生成一件商品，多件用锁定工作流组合。
7. 更大的 Klein 9B 保形更好，但它的许可和 4B 的 Apache-2.0 不同，商用前请先核对。

## 给后续视频工作流的建议

视频模型每一帧都在重画，商品走样只会比图片更严重，所以图片这一步的做法直接决定视频能不能用。

- **首帧用锁定工作流的成图。** 图生视频的商品一致性上限就是首帧，首帧走样后面全错。
- **让镜头和环境动，商品不动。** 缓慢推近、热气、光影移动、手入画，这些不要求模型重建商品的背面。让商品旋转或翻面必然走样。
- **首尾帧都锁定。** 支持首尾帧的模型可以两端都给实拍合成图，中间的漂移会小很多。
- **素材现在就按复用准备。** 透明底抠图、配置 JSON、哈希留档这套东西视频阶段可以原样接上。建议把抠图按 SKU、色号、视角归档，并保留高于 1024 的原始分辨率。
- **算力。** M4 24 GB 跑图片够用，跑图生视频会很吃力。你的文档里已经有双机方案，视频放 B 机是对的。

这一节是规划建议，视频工作流本身还没有搭。
